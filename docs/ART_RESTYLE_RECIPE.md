# 可用素材：以现有底图改画风（img2img，2026-10-12）

> **结论**：`img2img` 是本项目出图的**可行路线** —— 以现有 `main_bg.png` 为构图底、
> `denoising_strength = 0.40`，可以**保住构图只换画风**，且自动判据全部通过
> （纸面墨色 2.1~2.4%，基准 1.4% ⇒ **纸上没有字**）。
>
> 产物：`docs/screenshots/restyle/`（4 种画风 + 对比图 + 参照物）

---

## 一、为什么必须换到这条路（重要复盘）

前面 **txt2img 出的二十多张全部不合格**。根因不是画风、也不是底模，而是：

> **txt2img 的构图完全随机**，我无法稳定得到"**下半书案 + 上半街景 + 空白信纸**"这个具体版式。

实测过的失败模式（每种都出过至少一张）：

| 失败模式 | 例子 |
|---|---|
| 出成"空房间内景" | `regen_newbase_guofeng3.png` |
| 出成"窗外山景的凉亭" | `desk/gf3_s313131.png` |
| 出成"木雕特写" | `desk2/gf3_s202601.png` |
| 出成"一排空白纸/木板" | `ink_r2_*` |
| 出人物 / 出书法字与红印章 | `regen_i2i_with_text.png`、`regen_ink_with_people.png` |

**而 `main_bg.png` 的构图本来就是对的**（下半书案：笔筒/砚台/空白信纸/笔架/算盘；
上半虚化街景；暖棕低饱和）。所以正确做法是**保住它的构图、只改画风**。

---

## 二、可用配方（已实测）

```
底图  main_bg.png            构图不动
接口  POST /sdapi/v1/img2img
底模  3Guofeng3_v34.safetensors   （SD1.5；4Guofeng4XL 在本机会出 NaN，见 §四）
参数  denoising_strength = 0.40   ← 关键：0.55 会破坏结构
      steps 30 / cfg 7.0 / DPM++ 2M Karras / seed 909090
      --no-half-vae（防 NaN）
```

### 四种画风（都按 d0.40 出，判据全过）

| 文件 | 画风 | 结构差异 | 纸面墨色 |
|---|---|---|---|
| `flat_d40.png` | 平涂矢量、细描边、暖棕限量色 | 4.1 | 2.4% |
| `gouache_d40.png` | 水粉、柔和笔触、绘本感 | 3.9 | 2.1% |
| `line_d40.png` | **线稿 + 淡彩**、fine outlines | **3.9** | 2.2% |
| `pixel_d40.png` | 16-bit 像素、抖动 | **3.7** | 2.2% |

（参照物纸面墨色基准 = **1.4%**；结构差异越小 = 越保住构图。d0.55 那批结构差异 8.0~9.3，桌面已糊。）

**对比图**：`restyle_grid.png`（左上是参照物，其余 8 格是 4 画风 × 2 强度）

## 三、自动判据（`tools/check_restyle.py`）

三项，都可量、不靠感觉：

1. **结构差异**：与参照物做 12×12 分块平均色差。>26 判"结构崩"
2. **纸面墨色占比**：在信纸区域统计"暗且低饱和"像素 —— 这是**本项目禁文字硬规矩**的自动检查
3. **画风距离**：另见 `tools/art_check.mjs style`

⚠️ **本判据第一版有 bug，已修**：区域用了**固定绝对坐标**（按参照物 2730×1535 算的），
而 img2img 输出是 **1152×648** ⇒ crop 出界、PIL 用黑色填充 ⇒ **每张都报"纸面墨色 100%"**。
**信号是"全表都是同一个可疑值"**（且参照物自己却是 1.4%）。修法是**按每张图的实际尺寸取相对区域**。

## 四、过程中修掉的三个真问题

### ① 模型切换的验证逻辑错了（会导致"以为切了其实没切"）

原本用 `startswith(name[:12])` 判断是否切换成功 —— 两个模型名都含 `Guofeng`，
前缀会互相匹配 ⇒ 误判成功。**实测证据：两个底模产出的文件哈希完全相同**
（`57BAD48C0046143D`），即 4 张全是同一个底模出的。
**修法**：用**完整文件名**比对，并在切换后打印实际生效的 checkpoint。

### ② WebUI 切 SDXL 底模报 `RuntimeError: dictionary changed size during iteration`

懒加载检查点缓存时改字典。**修法**：切换前先调一次 `GET /sdapi/v1/sd-models` **预热缓存**。
（修后 `4Guofeng4XL` 切换成功。）

### ③ `4Guofeng4XL_v1125D` 在本机出 NaN

```
modules.devices.NansException: A tensor with NaNs was produced in Unet.
```

这也解释了它早先产出图上的 **3×3 分块接缝**。**目前判断**：该 SDXL 底模在本机
（RTX 2060 SUPER / torch 2.3.1+cu121）不稳定；**SD1.5 的 `3Guofeng3_v34` 可用**。
