## 二、P0：不换掉就不能给人看（4 项）

### ① 信纸底图 `letter.png` —— 最难的一项

- **水印位置**：原图 2364×1773，右下角 `[2047,1665 .. 2303,1714]`，6 个字形
- **为什么不能像另两张一样裁掉**：`letter.tscn` 里 4 个书写槽位（`SalutationSlot` / `BodySlot1-3` / `SignatureSlot`）的锚点是**按底图印刷栏线像素位置**手工对齐的。裁边会让整张底图平移，**全部栏线错位，槽位对不上字格**。这是 2026-09-12 才修好的 bug（commit `6449e6c`），不能碰回去。
- **正确做法**：重新生成无水印底图 → 用 `tools/art_check.mjs` 测新图的栏线位置 → 重新锚定 4 个槽位 → 截图做像素级复核（虚线边与印刷线重合）。
- 网格规格要求见 [`ART_PLAN.md`](ART_PLAN.md) §四（推荐 12 栏，5 个槽位各占连续 2 栏，两端各留 1 栏空白）。

### ③ 书写槽位的边界压在印刷栏线上，并溢出纸面 ✅ 已修（2026-10-11）

> **订正**：本清单初版把这条写成"槽位没有任何视觉样式、视觉上不存在"。**实测（headless 截图 + 像素量测）证明判断有误** —— `scripts/letter_slot.gd` 的 `_draw()` 一直在画黑色虚线边框，槽位是看得见的。真正的问题在**几何**：

**实测数据**（`tools/capture_letter.gd` 出图 + 像素量测）：

| 项 | 实测值 |
|---|---|
| 视口 | 1152 × 648 |
| 贴图实际绘制范围 | x 390..1130，**y 20..574**（741 × 555，比例 1.335 与底图一致） |
| `PaperArea` / `Background` 的 rect | x 390..1131，**y −65..661**（741 × 726） |
| → 差异 | `PaperArea` 相对贴图**上下各有 85px 死区** |

由此产生两个真实缺陷：

1. **横向**：槽位边界取的是印刷**栏线**位置（底图像素 316 / 664 / 1017 / 1361 / 1715），而不是**栏中心**（0.17085 / 0.31854 / 0.46657 / 0.6129 / 0.76155）。槽位正好压在栏线上。
2. **纵向**：锚点 `0.12 / 0.85` 落在上面那 85px 死区里，导致槽位纵向**溢出纸面上下边缘**。

**已采取的修复**（commit `a96a86a`）：

- 横向锚点改为栏中心 ±12% 内缩，槽位装进栏内、不再压线
- 纵向锚点按实测换算为 `0.117 / 0.882`，槽位收回纸面内
- 新增 `StyleBoxFlat` 槽位底色（暖白 30% 透明），"可放置区域"一眼可见
- 占位提示改浅褐半透明（`PLACEHOLDER_COLOR`），与放下后的墨色（`FILLED_COLOR`）区分

**复核方式**：改完必须重跑截图，确认虚线边与印刷线的关系。这是 ART_PLAN §四 ③ 要求的"截图 → 像素验证"三步的第三步。

**修复前后的存档**（后续替换底图时可用作回归对照）：

| 文件 | 说明 |
|---|---|
| [`screenshots/letter_slots_before.png`](screenshots/letter_slots_before.png) | 修复前：槽位压在栏线上、纵向溢出纸面 |
| [`screenshots/letter_slots_after.png`](screenshots/letter_slots_after.png) | 修复后：槽位装进栏内、收进纸面 |
| [`screenshots/letter_slot_zoom.png`](screenshots/letter_slot_zoom.png) | 放大 3 倍：占位提示与虚线边细节 |

## 三、P1：影响"看起来像个成品"（5 项）

| # | 问题 | 位置 | 说明 |
|---|---|---|---|
| ⑤ | **主界面 `MainPanel` 是完全透明的**（`bg_color` alpha = `0.0`） | `main.tscn:11` | 面板等于不存在，所有文字直接浮在背景图上，没有层次。要么给它一个半透明纸色底，要么直接删掉这个 Panel |
| ⑥ | **NPC 没有头像** | `main.tscn` NPC 列表 | `NPCManager` 的 `avatar` 字段**已就绪但未启用**（`DEV_PLAN.md` 阶段 1）。当前列表只有文字，主界面看起来是一堆文本行 |
| ⑦ | **字体不统一** | 全局 | 只有信纸正文通过 `letter.gd:25` 加载了书法字体。**UI 上所有 Label / Button 用的是 Godot 默认字体**（无衬线）。书法信纸 + 现代无衬线按钮，风格直接打架。需要给全局 Theme 指定中文字体 |
| ⑧ | **全部按钮是 Godot 默认控件** | 所有场景 | `开始游戏/继续游戏/退出游戏`、`开始今日/结束今日/保存并退出`、`提交/重新填写/返回主界面` —— 清一色默认灰按钮，无九宫格底、无悬停反馈。`ART_PLAN.md` 的「按钮九宫格 9-slice」为缺失项 |
| ⑨ | **窗口分辨率是隐式的** | `project.godot` | 未显式声明 `window/size`，吃默认 1152×648；而信纸槽位对齐**依赖这个隐式默认值**。一旦有人改了窗口设置或换默认值，槽位会集体错位。应显式写死 |

## 六、可直接执行的复核命令

```bash
# 检测水印（近白低饱和平铺文字）
node tools/art_check.mjs watermark <图片路径>

# 裁出水印区域供人眼复核
node tools/art_check.mjs crop <底图> --box <bbox 外扩 40px> --out <输出.png>

# 数值平衡模拟
node tools/balance_sim.mjs
```

> 检测器只针对**白色/近白文字**。深色、彩色或极低对比水印会漏检，重要素材仍须人眼复核。
