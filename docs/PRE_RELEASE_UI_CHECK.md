### ① 信纸底图 `letter.png` —— 最难的一项

- **水印位置**：原图 2364×1773，右下角 `[2047,1665 .. 2303,1714]`，6 个字形
- **为什么不能像另两张一样裁掉**：`letter.tscn` 里 4 个书写槽位（`SalutationSlot` / `BodySlot1-3` / `SignatureSlot`）的锚点是**按底图印刷栏线像素位置**手工对齐的。裁边会让整张底图平移，**全部栏线错位，槽位对不上字格**。这是 2026-09-12 才修好的 bug（commit `6449e6c`），不能碰回去。
- **正确做法**：重新生成无水印底图 → 用 `tools/art_check.mjs` 测新图的栏线位置 → 重新锚定 4 个槽位 → 截图做像素级复核（虚线边与印刷线重合）。
- 网格规格要求见 [`ART_PLAN.md`](ART_PLAN.md) §四（推荐 12 栏，5 个槽位各占连续 2 栏，两端各留 1 栏空白）。

### ③ 书写槽位的边界压在印刷栏线上，并溢出纸面 ✅ 已修（2026-10-11）

> **订正**：本清单初版把这条写成"槽位没有任何视觉样式、视觉上不存在"。**实测（headless 截图 + 像素量测）证明判断有误** —— `scripts/letter_slot.gd` 的 `_draw()` 一直在画黑色虚线边框，槽位是看得见的。真正的问题在**几何**：

**实测数据**（`tools/capture_letter.gd` 出图 + 像素量测）：

| 项 | 实测值 |
|---|---|
| 视口 | 1152 × 648 |
| 贴图实际绘制范围 | x 390..1130，**y 20..574**（741 × 555，比例 1.335 与底图一致） |
| `PaperArea` / `Background` 的 rect | x 390..1131，**y −65..661**（741 × 726） |
| → 差异 | `PaperArea` 相对贴图**上下各有 85px 死区** |

由此产生两个真实缺陷：

1. **横向**：槽位边界取的是印刷**栏线**位置（底图像素 316 / 664 / 1017 / 1361 / 1715），而不是**栏中心**（0.17085 / 0.31854 / 0.46657 / 0.6129 / 0.76155）。槽位正好压在栏线上。
2. **纵向**：锚点 `0.12 / 0.85` 落在上面那 85px 死区里，导致槽位纵向**溢出纸面上下边缘**。

**已采取的修复**（commit `a96a86a`）：

- 横向锚点改为栏中心 ±12% 内缩，槽位装进栏内、不再压线
- 纵向锚点按实测换算为 `0.117 / 0.882`，槽位收回纸面内
- 新增 `StyleBoxFlat` 槽位底色（暖白 30% 透明），"可放置区域"一眼可见
- 占位提示改浅褐半透明（`PLACEHOLDER_COLOR`），与放下后的墨色（`FILLED_COLOR`）区分

**复核方式**：改完必须重跑截图，确认虚线边与印刷线的关系。这是 ART_PLAN §四 ③ 要求的"截图 → 像素验证"三步的第三步。

**修复前后的存档**（后续替换底图时可用作回归对照）：

| 文件 | 说明 |
|---|---|
| [`screenshots/letter_slots_before.png`](screenshots/letter_slots_before.png) | 修复前：槽位压在栏线上、纵向溢出纸面 |
| [`screenshots/letter_slots_after.png`](screenshots/letter_slots_after.png) | 修复后：槽位装进栏内、收进纸面 |
| [`screenshots/letter_slot_zoom.png`](screenshots/letter_slot_zoom.png) | 放大 3 倍：占位提示与虚线边细节 |

### ④ 词库区 `WordPanel` 背景透明 ✅ 已修（2026-10-11）

`letter.tscn` 的 `WordPanel`（左侧词库区）原本是 `type="Panel"` + `StyleBoxEmpty`，即**完全透明** —— 词库按钮直接压在背景上，既看不清边界也不像"呈放文书的案盘"。

**已采取的修复**：

- 新增 `StyleBoxFlat_wordpanel`：暖褐底（`Color(0.905,0.843,0.741,0.78)`）+ 棕褐描边 + 6px 圆角，取自 `ART_PLAN.md` §二 的"木构/家具"色板（`#9c5424`/`#b46c3c`）
- 词库按钮一并改色：暖纸底（`Color(0.976,0.949,0.878,0.92)`）+ 墨褐字（`Color(0.235,0.176,0.098)`），
  悬停/按下有独立配色，取代原先的 Godot 默认冷灰按钮 —— 冷灰压在暖褐底板上有明显色偏
- 按钮样式在 `scripts/letter.gd` 的 `_style_word_button()` 里以代码构建（按钮是运行时 `Button.new()` 出来的，无法在场景里预设）

**同时修正的一处交互细节**：槽位放下词之后**不再显示虚线边框**（`letter_slot.gd` 的 `_draw()` 增加 `if _has_word: return`）。
虚线是"这里可以放东西"的提示，放好了就该收掉；否则五个虚线框会一直和书法字抢视线。

**功能回归验证**：新增 `tools/verify_drop.gd`，模拟把五个正确词分别投放到五个槽位，断言
「槽位接受 → 文字更新 → 字色为墨色 → `player_answers` 同步 → `JudgeSystem.judge()` 返回 PERFECT」。
实测 `result_code = PERFECT`、`fee = 20`，**样式改动未破坏拖拽与判定**。

```bash
godot --path . --script res://tools/verify_drop.gd
godot --path . --script res://tools/verify_drop.gd -- --shot out.png   # 顺便截"已填好"的图
```

### ⑤ 的修复记录（`0b3c34a`）

**实测问题**：`main.tscn` 的 `MainPanel` 是**全屏** `StyleBoxFlat` 且 `bg_color` alpha = `0.0`（等于不存在），
所有 Label 用默认白字直接浮在插画上 —— **白字压在明亮背景上基本读不出来**。

**修法有个坑**：直接给全屏面板补不透明底会把整张插画盖掉（那是浪费）。所以：

| 改动 | 说明 |
|---|---|
| 面板改成**顶栏** | `anchors_preset` 由 15（全屏）改为 10（顶宽），`offset_bottom = 250`，把下方的书案插画留出来 |
| 底色 | 暖纸色 `Color(0.965,0.933,0.867,0.92)` + 棕褐描边，与信纸、词库底板同一套色系 |
| 文字改色 | 状态栏/目标/委托标签由默认白字改墨褐 `Color(0.235,0.176,0.098)` |
| **移除 `ScrollContainer`** | 每日仅 3 位委托人，本不需要滚动；容器收窄后 `size_flags_vertical=4` 会让它**塌成 0 高度、NPC 列表整个消失**。`NPCList` 直接挂到 VBox 下，`main.gd` 的节点路径同步 |

**回归验证**：新增 `tools/capture_scene.gd`，支持任意场景 + 可选点击按钮后截图，
命令 `godot --path . --script res://tools/capture_scene.gd -- --scene main --click StartDayBtn --out out.png`。
截图对照见 `screenshots/main_before.png` / `main_after.png`。

### ⑫ 的订正与现状（`0b3c34a`）

**ART_PLAN 原话**是「round1 的 5 张已实测无水印，缩到 16–24px 即可」。**实测下来只有一半对**：

1. **5 张里只有 `cursor_r1_05` 是"一个孤立毛笔"**，另外 4 张（`r1_01`–`r1_04`）是**无缝墨纹图案**，缩到 24px 只会是一团墨斑，当光标不可用。
2. **5 张全是 `colorType=2`（无透明通道）**、纯色浅灰底 —— 直接缩放会带一个灰方块。必须先做去底转 alpha。
3. **即使用可用的那张**：我把它按亮度转成 alpha、裁到毛笔主体（原图 `x320..570, y115..470`）、输出 64×64，
   但在信纸底色上按真实尺寸预览（见 `screenshots/brush_cursor_sizes.png`）：**96px 是漂亮的墨迹，16–32px 就是一团墨点**。
   这不是处理失误，是原图（笔 + 飞白 + 纵向墨滴）缩小的必然结果。

**所以没有把它设为系统光标**（那尺寸下认不出是笔），改为用在放得大的地方：

- `word_button.gd` 的**拖拽预览**：毛笔贴图（72px）+ 词文本并排，取代原来的纯文字预览
- 预览构造抽成 `build_drag_preview()`，可被 `verify_drop.gd` 单测
  （教训：直接调 `_get_drag_data()` 时没有真实拖拽在进行，`set_drag_preview()` 会触发引擎断言
  `Condition "!get_viewport()->gui_is_dragging()" is true`）

**若想要真正的毛笔光标**，需要重新生成一张**单一笔尖、透明背景、方向朝上**的小图（128×128 内），
而不是从这批 832×832 的场景插画里裁。这条我标为**未完成**。
| ⑬ | 标题缺「代书」书法大字 | 兜底方案是用寒蝉活楷渲染，或直接不做 |

## 六、可直接执行的复核命令

```bash

node tools/art_check.mjs watermark <图片路径>
```
